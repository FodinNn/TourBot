# Гид по Казани — бот для MAX

Небольшой бот-гид для мессенджера MAX. Работает как разговорный путеводитель:
показывает главное о городе, рассказывает про Кремль и Бауману, советует, где
поесть эчпочмак, и помогает собрать маршрут на один день. Вся экскурсионная
часть лежит текстами в `internal/data` — если захотите сделать из бота гида по
другому городу, менять придётся в основном её.

## Что он умеет

- При запуске или слове «старт» показывает меню из шести разделов: must-see,
  храмы и мечети, современная Казань, еда, маршрут на день и «с детьми».
- Понимает ввод в свободной форме: «напиши 4» и «где поесть» ведут в один и тот
  же раздел, «баумана» открывает рассказ про главную пешеходную улицу, а
  «спасибо» вежливо прощается и ждёт следующего вопроса.
- По кнопке «Что рядом со мной?» запрашивает геопозицию и присылает три
  ближайших места по возрастанию расстояния — с точностью «350 м» или «1,3 км».
- В каждом разделе есть кнопка «Назад», так что заблудиться в меню сложно.
- Если запрос совсем не понят, честно признаётся и снова показывает меню.

## Как попробовать

Понадобится токен бота из MAX. Положите его в файл `.env` рядом с кодом:

```
BOT_TOKEN=ваш_токен
```

и запустите:

```
go run ./cmd/bot
```

Дальше просто откройте чат с ботом в MAX и нажмите «Начать» — дальше меню само
подскажет, что можно спросить.

## Как устроен код

Четыре небольшие пакета, каждый со своим простым делом:

- `cmd/bot` — точка входа: читает токен и запускает бесконечный цикл обновлений.
- `internal/bot` — всё общение с API MAX: long polling, отправка сообщений,
  клавиатуры и разбор пришедшей геопозиции.
- `internal/handlers` — «мозги»: решает, что ответить на введённый текст, и
  отдельно считает расстояния до достопримечательностей.
- `internal/data` — тексты экскурсии, список мест с координатами и словарь
  ключевых слов.

## Если захочется что-то поменять

Самое частое — добавить новое место или тему. Для этого достаточно дописать
запись в `internal/data/places.go` (название, эмодзи, координаты) и при
необходимости — пару ключевых слов в тот же файл. Тексты разделов живут в
`internal/data/texts.go` и копируются в бот «как есть».

## Тесты

`go test ./internal/...` — проверяют разбор запросов (цифры, названия, ключевые
слова, «пока» в разных видах) и подсчёт расстояний.

## Запуск в проде

Соберите бинарник и положите его вместе с юнитом на сервер:

```
go build -o tourbot ./cmd/bot
```

Затем на сервере (пути и пользователя можно поменять в `deploy/tourbot.service`):

```
sudo useradd --system --home /opt/tourbot --shell /usr/sbin/nologin tourbot
sudo mkdir -p /opt/tourbot /var/lib/tourbot
sudo cp tourbot /opt/tourbot/
sudo chown -R tourbot:tourbot /opt/tourbot /var/lib/tourbot
sudo sh -c 'echo BOT_TOKEN=ваш_токен > /etc/tourbot.env'
sudo chmod 600 /etc/tourbot.env
sudo cp deploy/tourbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tourbot
journalctl -u tourbot -f
```

Токен читается из `/etc/tourbot.env`, `.env` рядом с бинарником не нужен. Сервис
перезапускается сам при падении, а файл блокировки `BOT_LOCK_FILE` не даёт
запустить второй экземпляр: при одном токене два процесса делят между собой
очередь обновлений и часть сообщений теряется.

Если бот должен работать на машине разработчика, хватит пользовательского юнита
`deploy/tourbot.user.service`:

```
cp deploy/tourbot.user.service ~/.config/systemd/user/tourbot.service
systemctl --user daemon-reload
systemctl --user enable --now tourbot
journalctl --user -u tourbot -f
loginctl enable-linger $USER   # чтобы сервис поднимался без входа в систему
```

При старте бот снимает все webhook-подписки, которые мог оставить конструктор
или панель: пока подписка активна, MAX отдаёт события на её адрес, и long polling
получает пустой список — снаружи это выглядит как «бот не читает сообщения».
